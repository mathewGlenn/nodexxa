# DigitalOcean discovery and monitoring (Layer 1)

Discovery: teams/connections, projects, Droplets, App Platform services and deployments, managed DB metadata where permissions allow. Support resource pages, labels/tags, region, size, public/private address with appropriate access, status, current version where available. Accurately reflect actual DigitalOcean API capabilities; do not invent unsupported endpoints or metrics. Document exact API endpoints/scopes used and supported API fields. Project association can be many-to-many if DO API allows; use explicit join model rather than assume one project per host. Paginate all collections. Handle deletion, lost access, rate limiting, transient outages and team/account differences.

Monitoring: provider metrics if supported, recent time series, polling metadata, source and sample time. External HTTPS/HTTP checks with configurable timeout, redirect policy and check cadence; explicitly prevent SSRF to internal/private/metadata addresses with host/IP resolution validation including redirects, DNS rebinding and IPv4/IPv6. TLS expiry by certificate check. Status propagation when agent is absent. Keep explicit reliability semantics for partial failure.
