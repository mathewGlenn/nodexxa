# Implementation decisions

Where the specifications left room for interpretation, the more secure, narrow and testable option was chosen (CLAUDE.md rule). Each decision lists where it is enforced and tested.

| # | Decision | Why | Enforced in / tested by |
|---|---|---|---|
| D1 | **Agent credentials are Ed25519 key pairs generated on the host.** The server stores only the public key; every request is signed. | Satisfies both "store credentials hashed where possible" (nothing secret server-side — stronger than a hash) and "agent signs/authenticates requests". A database leak cannot be used to impersonate agents. | `server/utils/agentAuth.ts`; `tests/integration/agents.test.ts` |
| D2 | **Replay protection = timestamp window (±300 s) + strictly increasing per-agent sequence**, enforced with one atomic `UPDATE … WHERE lastSeq < $seq`. No nonce table. | Bounded storage, race-free, survives concurrency. Agent persists its last sequence (≥ wall-clock ns) so restarts never reuse a value. | `authenticateAgent`; replay/out-of-order tests in Node and Go |
| D3 | **Key rotation requires proof of possession**: request signed by the old key, carrying a signature by the new key. New key is written on the host only after the server accepts. | Prevents installing a key the agent cannot use; no window where the host holds an unregistered key. | `rotate-key.post.ts`, `client.go RotateKey`, real-binary E2E |
| D4 | **CSRF: Origin (or `Sec-Fetch-Site: same-origin`) must match the app's host for every cookie-authenticated mutation**, plus `SameSite=Strict` session cookies. | Framework-native, stateless, no token plumbing in forms. Agent endpoints use signatures, not cookies. | `server/middleware/01.security.ts`; `auth.test.ts` |
| D5 | **Passwords: scrypt (N=2¹⁷, r=8, p=1)** via Node's built-in crypto; sessions are random 256-bit tokens stored as SHA-256. | Reputable KDF without a native dependency; DB leak does not reveal live session tokens. | `server/utils/crypto.ts`, `auth.ts` |
| D6 | **No web bootstrap / default credentials.** The first owner is created with `cli.ts create-admin` (password via env or stdin). Further users join through one-time, hashed, 72 h invitation links. Only existing owners/admins can create additional workspaces. | Removes the "first visitor becomes admin" race and default passwords. | `scripts/cli.ts`, `invitations/*` |
| D7 | **DigitalOcean tokens: AES-256-GCM with a key ring** (`NODEXXA_ENCRYPTION_KEY` + `_KEY_ID`, older keys in `_KEYS_PREVIOUS`). Associated data = `connection:<id>` binds a ciphertext to its row. A rotated token must belong to the same DO team. | Authenticated encryption; key rotation without downtime (`cli.ts rotate-encryption-key`); swapping ciphertexts between rows fails; prevents silently merging two accounts' inventories. | `crypto.ts`; `crypto.test.ts`; `connections.test.ts` |
| D8 | **A missing token scope disables only that resource type** (`capabilities.droplets = "forbidden"` etc.) instead of failing the whole sync; any other list error aborts the sync **before** writing, so inventory is never partially erased. | "Lost access" ≠ "deleted". Failed syncs keep data and mark it stale. | `sync.ts`; `connections.test.ts` |
| D9 | **Vanished resources are marked `missingSince`, not deleted**; retention removes them after 30 days. | History is not lost abruptly on transient provider glitches. | `sync.ts`, `retention.ts` |
| D10 | **Agent ↔ Droplet links are always explicit admin actions** in the same workspace. Hostname matches are shown only as suggestions. | Spec: never trust agent-supplied identifiers across accounts. | `agents/[id].patch.ts`; `agents.test.ts` |
| D11 | **Uptime checks resolve DNS once per hop, reject the hop if *any* address is private/loopback/link-local/CGNAT/multicast/reserved (IPv4 and IPv6, incl. IPv4-mapped/NAT64/6to4/Teredo), then connect to the validated IP** (pinned `lookup`). Redirects are followed manually (max 5) and every hop is re-validated; URLs with credentials are refused. | SSRF, DNS rebinding, redirect-to-metadata. | `probe.ts`; `probe.test.ts` |
| D12 | **Health semantics:** a process is healthy only when positively observed running; a never-run check, never-reporting agent or missing metric is *unknown*. Charts break lines across gaps instead of interpolating; empty metric windows are labelled with the reason (scope missing / no DO agent / not polled). Threshold rules ignore samples older than 5 min (agent) / 20 min (DO). | "Missing telemetry is unknown, not zero." | `views.ts isProcessHealthy`, `alerts.ts`, `MetricChart.client.vue` |
| D13 | **Alert semantics:** condition must hold `durationSec` before opening; must be OK for `min(durationSec, 600 s)` before resolving (hysteresis); recurrence within `cooldownSec` reopens the same incident without a new notification; at most one unresolved incident per dedup key is guaranteed by a **partial unique index**. | Dedup + cooldown that also holds under concurrent evaluators. | `alerts.ts`; migration `incident_open_dedup`; `alerts.test.ts` |
| D14 | **Viewers may acknowledge incidents** (on-call workflow) but cannot resolve, nor change rules, channels, checks, connections, agents or members. | Acknowledge is not a configuration change. Narrowest useful permission. | `incidents/[id].post.ts`; `auth.test.ts` |
| D15 | **Background work runs only in the separate worker process.** Work items are leased with `FOR UPDATE SKIP LOCKED` + expiring leases; singleton tasks (alerts, retention) use transaction-scoped advisory locks (session locks are unsafe with a connection pool). | Multiple worker replicas never double-process. | `scheduler.ts`; scheduler tests |
| D16 | **Rate limits live in Postgres** (fixed window), keyed per IP and per account/agent. Per-IP thresholds are configurable for deployments behind a trusted proxy. | Holds across app instances without Redis. | `http.ts hitRateLimit` |
| D17 | **Docker collector is opt-in and uses only `GET /containers/json`**; never `inspect`. PM2 is collected for the agent's own user (PM2 is per-user); monitoring other users means running another agent instance as that user. | Root-equivalent socket access must be a deliberate choice; inspect exposes env/secrets. | `collect/docker.go`, `collect/pm2.go` |
| D18 | **Nginx: only `server_name`, `listen` and `ssl_certificate` directives are read**; certificate files are parsed for CERTIFICATE PEM blocks only (subject + expiry). No paths or config bodies leave the host. | Spec: no sensitive Nginx config. | `collect/nginx.go`; leak tests |
| D19 | **Agent transport: HTTPS only (plain HTTP accepted only for loopback dev servers), TLS ≥1.2, redirects refused, optional private CA file.** | Signed requests must never be forwarded elsewhere. | `client.go`; Go tests incl. untrusted-cert refusal |
| D20 | **Integration/E2E tests create a fresh uniquely named database per run** (non-destructive `prisma migrate deploy`) and drop only that database. `prisma migrate reset` is never used by tooling. | Tests can never wipe a developer's or production database. | `tests/integration/global-setup.ts` |
| D21 | **Theme preference is stored in a cookie (SSR-readable, applied by a blocking head script before paint) and on the user record**; login re-applies the user's choice. | No flash, no hydration mismatch, follows the user across devices. | `ThemeSelect.vue`, `login.post.ts`; `theme.spec.ts` |
| D22 | **DO metrics** use the Monitoring API (`monitoring:read`): CPU % is derived from per-mode counter deltas; memory/disk/load require DigitalOcean's metrics agent on the Droplet — empty results are shown as "no data", never 0. | Accurate to actual API behaviour. | `digitalocean.ts`; unit tests |
